Before the tool

Most good ideas die of paperwork, not physics.

A resident notices a real problem. A student sees an obvious fix. A civil servant knows exactly where a process breaks. What's usually missing isn't cleverness — it's a shared, rigorous, low-cost way to turn that noticing into a documented concept that a school, a council or a company can actually evaluate. That is the entire job of this file.

Three ways in

Built to be used alone, or handed to a room full of people.

One inventor

Work section by section at your own pace. Everything typed here stays on this device.

A classroom or cohort

A teacher or facilitator can run the pipeline as a single session or a multi-week unit — see the Facilitator section near the end.

An institution or policy team

Adopt the same structure as a shared intake standard for reviewing proposals, without adopting any particular proposal's conclusions.

Before you start

Optimizing anything can go wrong. This file is built to make that visible, not hide it.

Every project here carries a Safety + Stewardship gate: foreseeable misuse, lifecycle impact, accessibility, and who could be harmed if the concept works exactly as intended. It isn't a checkbox to clear quickly — it's the same discipline the rest of the tool applies to novelty and feasibility, applied to consequences.

13 • Data + Backup

Keep your invention data portable.

Data is saved in this browser using IndexedDB, with lightweight preferences in localStorage. Export JSON for durable backup or transfer.

Backup

Exports include your invention fields, evidence, experiments, generated ideas, checklist state, scoring and milestone progress. They never include your display preferences or your local usage insights, and importing a file never changes your own preferences.

Reset

This affects only this browser profile, and only the project content: your theme, language and insights settings stay as they are. Export first if the project matters.

Connectivity + offline behavior

This standalone file has no external dependencies and can run from file://. Browser-local data is available offline after the file is opened. A single local HTML file cannot honestly provide service-worker caching or background synchronization by itself; those require hosting and companion files.

If turned on, this counts which sections you open and roughly how long the tab stays active in this browser only — never sent anywhere, and there's no code path in this file that could send it anywhere. Turn it off or clear it at any time.

14 • Facilitator & Rollout

Hand this to a room, not just a person.

Guidance for running this tool with a class, a team, or as a standard intake pattern inside an institution — without changing anything about how any single project's data is handled.

One class period (45-75 minutes)

  1. Frame (10 min): each student or team names one real problem in Problem Lab. Skip perfection — a rough problem statement is enough to start.
  2. Diverge (15 min): deal a hand of idea lenses in the Idea Foundry. Ban judging ideas out loud during this step.
  3. Converge (10 min): pick one idea and write a one-sentence concept in Concept Spec.
  4. Stress-test (10 min): run the Safety + Stewardship gate together as a class, out loud, one item at a time.
  5. Share (10-20 min): print or copy the dossier; groups present their problem and concept, not their whole file.

Multi-week unit

  1. Week 1: Problem Lab, Idea Foundry and Morphology. Homework: talk to one real potential beneficiary.
  2. Week 2: Concept Spec and Experiment Studio. Build the cheapest safe prototype the Minimum Viable Proof field describes.
  3. Week 3: Evidence Ledger and Prior Art. Require at least one non-classmate source in the ledger.
  4. Week 4: Decision Matrix, Roadmap and the Invention Dossier. Grade the reasoning shown, not whether the score is high.

For an institution or policy team

Treat the 13-section pipeline as a shared intake standard rather than software to procure: any team can open this same file, or a copy of it, and produce a dossier in the same shape. That makes early-stage proposals comparable to one another without forcing them toward the same conclusion, and gives a reviewing body a consistent place to look for the safety and evidence sections specifically.

Because every copy of this file is independent and offline-first, standardizing on it does not require standing up new infrastructure, accounts, or a vendor relationship.

Student and participant privacy

Nothing typed into this tool leaves the device it is running on. There is no account, no login, and no server component to secure or breach. A teacher collecting dossiers from a class still needs an ordinary privacy-conscious process for that collection step itself (for example, printed hand-ins or files submitted through the school's existing system) — this file's privacy guarantee is only that it introduces no new collection point of its own.
